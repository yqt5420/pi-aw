# vision-router

视觉通道自动维护与智能路由——**让任何（纯文本）模型都能识图**。

维护一个"哪些模型能识图"的通道列表，实际验证模型视觉能力，把视觉请求智能路由到可用视觉通道；不可用/识别失败时自动故障转移到下一个，最后兜底到免费外部 GLM-4V-Flash / Agnes。

## 功能

- 自动维护视觉通道列表 + 实测模型视觉能力（用真实插画图 + 确定性锚点验证）
- 智能路由视觉请求 + 自动故障转移（同 provider 优先 → 其他视觉模型 → 免费兜底）
- `vision_analyze` 工具：分析图片文件，选可用视觉通道
- 外部免费 GLM / Agnes 兜底

## 命令

- `/vision-status` — 查看当前视觉通道状态
- `/vision-scan` — 重新扫描/验证哪些模型能识图
- `/vision-test` — 测试视觉通道

## 配置（环境变量，密钥走这里）

| 变量 | 作用 |
|------|------|
| `GLM_API_KEY` | 外部 GLM-4V-Flash 兜底 key |
| `AGNES_API_KEY` / `AGNES_BASE_URL` | 外部 Agnes 视觉兜底 |

## 工作原理（零后台开销）

不跑常驻扫描；按需验证 + 智能路由，未用视觉时无额外开销。

## 图证实测（v3）

扫描时对每个可用模型发一张**内镶的真实治愈系插画**（抱着冰饮的小狮子，415KB，base64 内嵌于源码，自包含、无外部路径依赖），并问确定性锚点问题「图中是什么动物」。答对 `lion/狮子` 才算确认支持视觉；明确拒绝看图 → 标为不支持；有回应但没命中锚点 → 标为 `ambiguous`（疑似能看，路由仍会尝试，不误杀）。

> 背景：v2 用 JS 自造合成数字 PNG 做图证，很多网关解码不了合成图，模型看到花屏瞎猜数字，被误判成「不支持视觉」，导致能真识图的通道全被拉黑、只剩一个 kimi。v3 改真实图后实测可正确识别出多个视觉通道。

- `test.jpg`：该测试图源文件（仅作取回 base64 重生成的资产；运行时用内镶的 base64，不依赖此文件）。

## 超时

单通道测试/路由超时均为 90s（此前 30s 太紧，慢通道生成详细描述时会撞墙超时）。
