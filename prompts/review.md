# 代码审查提示词

审查目标代码（默认审查 `git diff --cached` 的暂存改动；也可按需指定文件/路径/某个插件或模块范围）：
```
<target>
git diff --cached   （或指定文件清单/目录）
</target>
```

从五个维度审查，输出**分级可执行报告**。只读审查，不得修改任何文件。

## 1. 健壮性（Robustness）
- 错误处理：异常吞没、失败兜底、回滚、资源释放
- 网络/瞬时失败：是否有重试或至少不静默中断；超时是否受控（AbortSignal 等）
- 并发与竞态：缓存读写、游标、并发单飞、fire-and-forget 追踪、TTL 失效
- 边界条件：空值、超大输入、截断、数组/循环终止、状态机遗漏

## 2. 功能性（Functionality）
- 与下游/服务端 API 契约是否吻合：字段名、类型、鉴权、幂等、乐观锁
- **声明与实现是否一致**：返回类型是否撒谎、注释是否与实际契约矛盾、是否遗漏 create/upsert 等能力边界
- 需求是否闭环：创建/删除/搜索/读是否齐全，有无死代码/永不触达分支
- 工具/命令的可见性（注入的指南或清单）与实际上注册的集合是否一致（单一事实来源）

## 3. 安全性（Security）
- 路径穿越：绝对路径、`..`、URL 编码/双重/多重编码绕过、反斜杠、null 字符
- 注入：命令注入、脚本注入、模板注入
- 密钥/token：是否会泄漏到日志、错误信息、工具输出；at-rest 明文落盘是否必要与最小化
- URL 拼接：尾斜杠、端口推导、SSRF、不可信输入拼 URL
- 危险操作（删除/批量删除）是否有确认与权限边界

## 4. 性能优化（Performance）
- 不必要的重复请求：是否每次先查再写（可用缓存/单飞去重）、可用 `expected_version` 透传避免多余往返
- 每轮 token / 上下文占用：工具 schema 体积、注入到 systemPrompt 的内容是否有上限/截断、是否有按需/懒加载
- 大内容处理：超长响应截断、过大循环/嵌套、算法复杂度

## 5. 屎山 / 可维护性（Maintainability）
- 重复代码、魔法数、命名、死代码、类型撒谎
- 注释与实际契约矛盾、过时注释
- 单一事实来源：工具集与指南、计数与实现是否一致
- 是否有更简单/可收敛的实现，是否值得保留、重构

## 分级标准
- 🔴 **严重**：会导致功能错误、安全事故、或链路**静默失败**的（必须修）
- 🟠 **中等**：契约/逻辑缺陷或明显低效（应修）
- 🟡 **轻微**：边界/防御性/代码质量问题（可选）
- 🔵 **建议**：测试覆盖、常量化、文档补充

## 输出格式
对每条问题给出：
```
【文件:行号 / 函数名】问题描述 → 建议修复
```
按 🔴→🟠→🟡→🔵 分组排列，正文中间不要跳过任何你实际发现的问题。

最后给一段**总体结论**：这段代码值得保留还是需重构 + 是否可合入 + **修复优先级排序**（先修哪个，为什么）。

> 说明：本提示词既用于暂存改动的快速审查，也用于对某个插件/模块/能力做深度审查；审查前需明确 target 边界，避免范围越大越含糊。
